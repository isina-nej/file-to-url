# ارزیابی سازگاری و محدودیت‌های پلتفرم Telegram Serverless

این سند نتایج تطبیق و ارزیابی سازگاری FileLink Bot با نسخه جدید Telegram Serverless Isolate Runtime و `@tgcloud/cli` را تشریح می‌کند.

## ۱. ویژگی‌ها و محدودیت‌های تأیید شده

| ویژگی پلتفرم | وضعیت سازگاری | راهکار پیاده‌سازی شده در پروژه |
| :--- | :--- | :--- |
| **محیط اجرا (Runtime)** | V8 Isolate بدون Node.js APIs | کدنویسی در ماژول‌های ES خالص، بدون وابستگی به `fs`, `path`, `process.env`, `Buffer` |
| **مدیریت فایل** | عدم دسترسی به File System دیسک | کپی مستقیم پیام به کانال با `api.copyMessage` بدون نیاز به ذخیره فایل روی دیسک |
| **وابستگی‌های npm** | در زمان اجرا در Isolate در دسترس نیستند | تمامی ماژول‌های پروژه از متدهای استاندارد بومی جاوااسکریپت و SDK رسمی سرورلس استفاده می‌کنند |
| **پایگاه‌داده** | SQLite داخلی با SDK رسمی `sdk/db` | طراحی اسکیمای رسمی در `tgcloud/schema.js`، عدم استفاده از Foreign Key و انجام بررسی‌های یکپارچگی در سطح کد |
| **کنترل انقضا** | نبود پردازش پس‌زمینه دائمی یا Cron | ارزیابی تنبل (Lazy Expiration) در لحظه درخواست دریافت دیپ‌لینک |
| **تولید توکن تصادفی** | نیاز به RNG امن رمزنگاری | استفاده مستقیم از `globalThis.crypto.getRandomValues` موجود در استاندارد V8 Isolate |
| **ارقام فارسی/عربی** | ورودی‌های کاربران تلگرام | نرمال‌سازی خودکار ارقام ۰-۹ و ٠-٩ به اعداد انگلیسی قبل از محاسبات ریاضی |
| **تنظیمات و متغیرها** | نبود `process.env` در ایزولیت | خواندن کانفیگ از جدول `app_settings` در دیتابیس با کش درون‌حافظه‌ای درخواست |

## ۲. ملاحظات امنیتی Bot API

1. **مدیریت محدودیت نرخ (429 Too Many Requests):**
   - در لایه `rate-limit.js`، پیش از فراخوانی تلگرام، تعداد تلاش‌ها با پنجره لغزنده مبتنی بر دیتابیس ارزیابی می‌شود.
2. **عدم افشای اطلاعات کانال و لاگ‌ها:**
   - شناسه کانال، استک تریس خطا و توکن‌های دسترسی در پیام‌های خروجی به کاربران نمایش داده نمی‌شوند و در لاگ‌های JSON ماسک می‌گردند.
3. **حفاظت در برابر همزمانی و Callbackهای منسوخ:**
   - هر نشست آپلود دارای فیلد `session_version` است و عملیات با شرط نسخه انجام می‌شود تا Callbackهای تکراری وضعیت سیستم را خراب نکنند.
